# かがやきライフタウン大垣2026「まるごと体験ビンゴ」システム

対象イベントは「かがやきライフタウン大垣 秋のつどい」（2026年11月1日、大垣城ホール）です。デジタルビンゴカード、スタンプQR、紙とデジタルの抽選受付、ガラガラ2台の手入力と自動読取（C2）、共有景品の確保、引換券の発券と引換、立体の会場Webマップを、研究室のLinuxサーバー1台で動かします。引換券は、WindowsPCに接続したレシートプリンター MP-B20（58mm）へ、ブラウザから印刷します。

## 画面

| URL | 使う人 | 内容 |
|---|---|---|
| `/visitor/` | 来場者のスマホ | 市が承認した構成（右上におがっきぃ）に紙カードのマスを載せたデジタルカード、マスをタップしてスタンプQRを読取（⑤はタップで達成）、受付用QR、立体会場マップ、年代・性別・満足度を数値で集計するアンケート、終了時刻と景品切れの案内。スクロール不要の1画面構成 |
| `/staff/` | スタッフ（WindowsPC、ガラガラ1のiPad、ガラガラ2のPixelタブレット） | 受付（デジタルQR、紙の手入力、C1読取の確認）、出玉の色入力、確定、引換、在庫、補充と戻し、機器状態、履歴、設定 |
| `/print/` | WindowsPC（MP-B20を接続） | 印刷待ちの引換券を1件ずつ印刷し、排紙を確認。iPadやPixelタブレットでも開けるが自動印刷はしない。同じ券を2台の端末が刷らないよう、サーバーで印刷を引き受けた端末を1つに限る |
| `/camera/` | WindowsPC（カメラ3台） | カード用カメラでデジタルカードのQRと紙カードのシールを読み取り、ガラガラ1か2のタブレットへ送る。玉用カメラ2台は色の候補を出すだけ（精度未検証） |
| `/admin/` | 運営の管理者（ベーシック認証） | 景品と受付の集計、ガラガラの状態、操作ログ、CSV、景品切れ時の「新規受付終了」の切替。来場者画面に小さなリンクがある |

来場者向けの案内iPadは2026-10-28の構成変更で廃止しました。

## 構成

```text
server/                 Node.js（ES Modules）+ Fastify + node:sqlite
  src/domain/           抽選、カード、在庫の業務規則（DOM、HTTP、DBに非依存）
  src/db/               接続、番号付きmigration、repo
  src/services/         トランザクション、冪等性、認証、機器連携
  src/http/             ルート、認証認可、Origin検査、エラー応答
  scripts/              初期化、スタンプQR生成、機器トークン、バックアップ、機器シミュレーター
  test/                 node:test（domain、HTTP、再起動、復元）
web/                    ビルド工程なしのHTML、CSS、JavaScript
deploy/                 systemd、Caddy、バックアップのひな形
docs/                   仕様書、決定事項、導入手順、操作手順、API、マップ形式
stamp-qr/               生成したスタンプQR（Git管理外。ZIPには --with-qr で同梱）
```

抽選と景品在庫の正本はサーバーのSQLiteです。1つの業務操作は1つのトランザクションで、抽選状態のスナップショット、操作履歴、冪等キー、カードの使用済み化を同時に更新します。

## ローカルで動かす

Node.js 22.13以降が必要です。

```sh
cd server
npm install
npm test
node --disable-warning=ExperimentalWarning scripts/devSeed.js   # 開発用データ（本番では拒否）
npm run dev
```

`http://127.0.0.1:3000/visitor/` などを開きます。devSeedのスタッフは `admin`、`op1`、`op2`、`prize`、`printer`、パスコードは `dev-passcode` です。マップはサンプル配置で、正式な会場図ではありません。カメラによるQR読取はHTTPSかlocalhostでだけ動きます。

## 本番へ

`./build-zip.sh --with-qr` でZIPを作り、`docs/DEPLOY.md` の手順でサーバーへ移します。当日の操作は `docs/OPERATIONS.md`、会場PCの検出プログラム向けAPIは `docs/device-api.md`、マップデータの形式は `docs/map-data.md` にあります。

## まだ決まっていないこと

運営の承認が必要な事項と、承認がないまま安全側で暫定実装した事項は `docs/DECISIONS.md` にあります。特に、紙カードの二重受付防止（C04）、会場PC停止時の継続条件（C01）、手書き券（C05）、アンケートの設問（C16）、公開ドメイン（C25）、プリンター機種と用紙幅、玉の手持ち数、正式な会場配置とステージ演目は未確定です。本番前の確認項目は `docs/CHECKLIST_BEFORE_PRODUCTION.md` です。
