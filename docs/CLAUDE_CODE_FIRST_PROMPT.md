# Claude Code Webへ最初に渡す依頼

このリポジトリの `CLAUDE.md`、`README.md`、`docs/requirements.md`、`docs/DECISIONS.md`、`docs/IMPLEMENTATION_PLAN.md` を読んでから着手してください。仕様書の正本を勝手に書き換えないでください。

最初にリポジトリ全体を調査し、次の内容をレポートしてください。

1. 現在実装済みのもの、未実装のもの、テスト結果。
2. 仕様書の原文要件、提案、未決定事項の分類。
3. C01〜C08の選択肢、推奨案、運営の決定が必要な理由。
4. 2026年11月1日の本番に向けて、紙受付と手入力抽選を先に成立させる最小実装範囲。
5. 次に追加するDB migration、サービス、HTTP API、テストの一覧。

レポートだけで作業を終えず、未決事項に依存しない範囲では、スターターを実行可能な状態に整え、`npm test` とヘルスチェックを実行してください。テストを実行した場合は出力と結果を報告してください。実装済みの機能を重複して作り直す必要はありません。

その後の業務機能は、まず承認済みの決定が揃っているかを確認してください。承認が必要な項目について、Claude Code自身の推奨を運営の承認とみなして実装を確定しないでください。安全な基盤作業は続け、業務ルールが不明な箇所では実装の停止理由、選択肢、影響範囲を明確にしてください。

差分を小さく保ち、各段階でテストしてください。未提供のブース情報、ステージの時刻、プリンター幅、ドメイン、初期玉数を創作しないでください。立体会場マップは必須ですが、未提供の正式配置や演目を仮の本番データとして登録しないでください。最後に、変更ファイル、実行したコマンド、テスト結果、未実装範囲、次の判断事項を報告してください。
